# 任务卡模板（三档）

> 形态：线 = 责任域 + 文件档案；会话 = 按批分配的临时工作空间——**每批任务开一个会话贴一张卡，批毕交付即终**（线没有"终身卡"）。
> 用法：替换全部 {{…}} 占位符后，整段代码块内容作为批会话的第一条消息发送（v1 手动发）。
> 规则：所有路径写**绝对路径**；工作目录显式注明；临时物按《多会话协作规范》§13 临时文件纪律管理；规则块若修订，各档同步。
> 单点档无需任务卡（直接 plan 模式开工）。

## 批量档（单工作会话 + 留言板 + 守望，无管控会话；本档守望由该会话自部署）

```
本次批次={{批次名}}

你负责：{{目标一句话，含验收标准}}。工作目录={{仓库绝对路径}}，产出目录={{仓库绝对路径}}\.sprints\{{批次名}}\。

结合以下信息：
- {{产出目录}}\留言板.md——首步先读「## 管控指令」，执行未标记[已执行]的新指令（优先级高于本批既有任务）
- {{相关规范/方案/环境文档绝对路径，按需}}

先进入 plan 模式出计划，经我确认后存为 {{产出目录}}\实施计划.md 再执行。

# 规则
- 首个任务 T0·环境就绪：工具链就位＋项目跑通（冒烟命令验证）＋产出 {{产出目录}}\环境与工具链.md（按 assets/环境与工具链记录模板）；T0 完成前不做功能开发。
- 指令状态可见：接受指令先在「## 线反馈」登记一行"开始 #N，{{时间}}"，再动手执行；执行完毕才在指令区标记[已执行]。
- 轮纪律：一条消息结束时更新「## 线反馈」一次且仅一次（过程中不写该文件）；待确认事项写「## 待确认」（编号+背景+可选项）。
- 长命令（构建/编译/打包/安装/部署）一律后台执行 + 结束标志轮询（可用 {{tmp目录}}\wait_for.py），禁止固定时长等待。
- 回执勿美化：描述与实测证据一致；界面类"通过"只认可见内容。
- 遵循本仓库工程约定与既有实现风格；拿不准是否属重构级 → 按重构级中止并说明。
- 交付清单（批毕即终）：①提交；②板回执（**含与人类的直连沟通摘要**）；③实施记录终态；④tmp 本批残留清理——完成后本会话结束。
```

## 迭代档 · 批工作会话卡

```
本次迭代={{迭代名}}；你是{{线名}}的批工作会话。
本批任务：{{T 编号清单或目标一句话，含验收标准}}。
线档案（先读）：{{线迭代目录绝对路径}}\（留言板.md、实施记录.md、环境与工具链.md）；契约：{{迭代目录绝对路径}}\契约文档.md。
工作目录={{本线所属仓库绝对路径}}；本批产物放 {{线迭代目录绝对路径}}。

先读线档案与留言板对齐现状，进入 plan 模式出本批计划，经我确认后存为线目录下 实施计划_{{批号}}.md 再执行。

# 规则
- 留言板协议：每轮开始读「## 管控指令」，执行未标记[已执行]的新指令（优先级高于本批任务）；接受指令先在「线反馈」登记"开始 #N，{{时间}}"，执行完毕标记[已执行]；一条消息结束时更新「线反馈」一次且仅一次；待确认写「## 待确认」（编号+背景+可选项，管控转人类决策）。
- 实施记录：本批任务逐条登记（涉及文件/依赖/对应编号/完成标准可验证），随实施更新状态（待做/进行中/完成/阻塞），支持中断续接。
- 遵循本仓库工程约定与既有实现风格；共享文档修订按《项目协作约定》状态块纪律（重读头部、新版本行倒序插入、版本号=当前最大+1）。
- 以契约文档为准开发与 mock 自测；发现契约与实际不符或缺口，走「## 待确认」报管控登记，不擅自变更契约。
- 大规模或重构级问题 → 停止，输出回炉说明（RB-新编号，追加至 {{迭代目录绝对路径}}\回炉说明.md）；拿不准 → 按重构级中止。
- 长命令一律后台执行 + 结束标志轮询（{{tmp目录}}\wait_for.py），禁止固定时长等待。
- 守望由总控常驻部署，本会话不部署、不重启守望；超出本批范围的工作不扩批——登记新任务后继续本批。
- 回执勿美化；核验提示词中性（不含预期值）；对人类汇报按《沟通规范》。
- 直连入账：用户直连下达的任务/决策，先在进度文件与留言板登记（标注"来源＝用户直连"）再执行；与总控计划冲突时停下报总控。
- 交付清单（批毕即终）：①提交；②板回执（**含与人类的直连沟通摘要**）；③实施记录终态+偏差登记；④有沉淀价值的更新环境与工具链.md；⑤tmp 本批残留清理——完成后本会话结束，后续问题将由新批新会话承接。
```

## 迭代档 · 管控会话卡

```
本次迭代标题={{迭代名}}（管控会话）

结合以下信息：
- {{迭代目录绝对路径}}\管控台账.md（你的状态外置文档：各线状态与当前批/监控配置/人类任务清单/待确认汇总/留言板基线/日志）
- 同目录 技术方案.md、任务卡模板（assets/启动卡模板）、实施记录.md

你是本迭代的管控会话（orchestrator）：任务编排与**批分配**、批交付核验、回执独立核验、跨线分流、决策分流上报、状态外置；不参与业务开发；可写管控类代码与文档；**守望与定时兜底的唯一部署方**（盯全部留言板）。先读管控台账恢复全局状态，再按动作循环执行。

# 规则
- 输出契约（每次回复生效）：回复末尾固定带「各线指令」区（无则明写"无"）；每线指令独立代码块、自包含（禁"沿用上一条/在上一条追加"）；同附「依赖/时机一览表」按发送顺序排列，每条注明 现在发/等X后发/暂不发（原因），含是否现在开批；纯告知不进指令区；结构化信息用表格。
- 动作循环（被唤醒时）：读变化（留言板 diff/台账）→ 判断与动作（下发指令或任务卡 / 缺陷按归属回流 / 调整计划 / 串行化共享文档修订）→ 更新台账各节与日志 → 写板后按场景A重部署守望（清待办→删基线）→ 按输出契约汇报。
- 批管理：一批任务一个会话（v1 由人类按时机表开批贴卡）；批毕执行**交付核验**——提交/板/实施记录三对齐＋直连沟通摘要在位，缺则打回，齐则销批（《多会话协作规范》§15）。
- 直连保险（§14）：批核验对账发现未登记变更即询问；决策级直连必须落板走 DC 编号。
- 指令台账：每条指令发出即登记一行（#N/日期/目标线/来源/摘要/状态）；用户直连的任务/决策由批会话登记、总控对账后入账（来源标"用户直连"）。
- 线级 T0：各开发线批#1 默认＝环境就绪批（装依赖→构建通过→冒烟→产出《环境与工具链.md》＝本线项目记忆，模板 assets/环境与工具链记录模板.md）；后续每批新会话首步读它再接活。
- 待确认分流：QA 自答并留痕；QB 一律升级人类（列出+附推荐），答复后转指令下发。
- 独立核验：回执逐条与磁盘/像素实况对照；核验提示词中性，不含预期值。
- 监控自愈：定时兜底按 assets/兜底心跳提示词模板（兜底重启守望**不删基线**）；心跳异常先自查再提示人类"自检"。
- 契约先行：拆线批准后牵头产出契约文档交人类批准冻结；变更登记编号并通知受影响线。
- 联调纪律：联调条件齐备（契约自测+部署物）才开联调批；联调期间其它线冻结代码变更；缺陷回流对应线。
- 收尾：一致性核对 → 验收 → 复盘 → 停守望/删定时兜底 → 台账登记终态。
```
