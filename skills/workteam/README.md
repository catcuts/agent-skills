# Workteam——多会话协作规程

按《多会话协作规程》组织 AI 会话团队协作：人类只做决策与验收，AI 会话自组织执行。覆盖开工定档（单点/批量/迭代三档）、留言板与管控台账、轮纪律驱动多线并行、回执独立核验、验收与复盘全生命周期。

适用于：开发迭代、问题修复、技术支持/问答、文档编写等一切需要多会话协作或队列化处理的工作。

## 安装

```
npx skills add catcuts/agent-skills    # 选择 workteam
```

## 三档速览

| 档 | 判据 | 构件 |
| --- | --- | --- |
| 单点档 | 不开第二个会话 | plan 批准 + `.docs/` 排查报告 |
| 批量档 | 开多会话，人类直接盯 | 留言板 + 守望 + 启动卡 |
| 迭代档 | 需管控会话代人类盯 | 拆线方案批准 + 多线留言板 + 管控台账 + 验收/复盘 |

判据一句话：要不要开第二个会话。详见 `references/规模适配规范.md`。

## 目录说明

- `SKILL.md`——薄入口：定档、冷启动序列、运行循环、异常路由、收尾序列、参考索引
- `references/`——规程权威源（8 份）：《项目协作约定》《多会话协作规范》《决策与台账规范》《规模适配规范》《验收报告规范》《报告修订规范》《信息记录规范》+ 自驱动方案全记录（v2 技术储备）
- `assets/`——模板与脚本：留言板 / 管控台账 / 三档启动卡 / 续接提示词 / 实施记录 / 复盘报告 / 四元预估模板 + `watch_board.py`（留言板守望）

## 环境前置与适配

- 守望脚本需 Python 3.8+（纯标准库）；以 `run_in_background` 后台运行、变化退出触发任务通知的语义以 ZCode 实证，其他 harness 降级为人工轮询（规程层 harness 无关，不受影响）
- v1 自驱动：初始消息手动发（启动卡）、守望不健康人工恢复（对会话说"自检"）；不依赖任何 AI 工具的 CLI 与数据目录
- `references/ZCode多会话自驱动工作方案…md` 中出现的盘符路径（ZCode 安装位置、数据目录等）为原作者实测环境记录，仅作学习参考，v1 运行不依赖其中任何内容

## 规程修订

`references/` 即规程唯一权威源，随本仓库分发。修订建议通过 Issue / Pull Request 提出；本地改动会在更新时被覆盖——skill 目录对使用者只读。
