# Workteam——多会话协作规程作业手册

一套"人类只做决策与验收，AI 会话自组织执行"的协作规程。你被调用时充当规程执行者：引导用户定档与启动，按规程组织会话协作，维护台账与核验纪律。

**第一原则**：一切状态外置于文件（留言板/管控台账/实施记录）。会话是易耗品，随时可死可换；文件是唯一事实源，消息不会丢只会慢。

## 0. 形态铁律（先于一切）

- **线 = 责任域 + 文件档案**：一条线守一个（或一组强耦合）项目；全部状态在线迭代目录的文件里（留言板/实施记录/环境与工具链/契约）。**线不等于会话。**
- **会话 = 按批分配的临时工作空间**：总控派批 → 会话在所属仓库目录装载线档案干活 → 批毕交付即终；后续问题开新批新会话。禁止"一条线一个会话走到黑"。
- **不得用会话内子智能体 / workflow 编排替代多线形态**，除非用户明示要求。
- 为什么：文件是唯一事实源，会话可死可换；短命会话每批只装载所需上下文（长寿会话每次唤醒重喂全部历史）；批批新鲜上下文，不积隐性误解。
- 会话内子代理仅限一次性辅助任务（环境部署、批量构建等），不可向人类提问，失败即返回问题报告。

## 1. 第一步：定档

判据一句话：**要不要开第二个会话**。

- 不开 → 单点档；开但人类直接盯 → 批量档；需要管控会话代人类盯 → 迭代档。
- 拿不准 → 就高不就低；档位构件表与升降档规则见《规模适配规范》。

## 2. 冷启动序列

### 2.0 通用四问（任何档位先问清）

1. 目标与交付物（一句话 + 验收标准）
2. 涉及哪些仓库/环境/账号
3. 外部依赖（设备/凭证/第三方）——立项即办清单
4. 期望日历窗口

### 2.1 单点档

plan 模式出计划 → 人类批准 → 执行 → 产物：`.docs/` 排查报告（按《报告修订规范》）。不开留言板、不部署守望。

### 2.2 批量档

1. 建工作目录 `.sprints\{{批次名}}\`：留言板（assets/留言板模板）+ 实施记录（assets/实施记录模板）+ `tmp\`
2. 任务逐条以指令写入留言板「## 管控指令」区
3. 复制 assets/watch_board.py 与 assets/wait_for.py 到 `tmp\`，**必做**：会话内后台部署守望（参数=留言板绝对路径）+ 建定时兜底（assets/兜底心跳提示词模板）
4. 输出任务卡（assets/启动卡模板·批量档），用户开会话贴入
5. 决策走简表：待确认区 → 人类批复 → 回写为指令

### 2.3 迭代档

1. 四问后产出**拆线方案**：按"仓库 × 依赖边界 × **职能内聚**"拆线——前后端/强耦合模块目录分离时优先同线（省去端间对接成本）；每线一段边界契约（对内职责/对外接口/依赖前提）；典型线型 = 开发线×N ＋ **联调线**（集成验证统一由它做，禁止各线各联调各的）＋（可选）设施线。拆线是方法、线数是结果，每个迭代重新推导
2. **【关卡】拆线方案 + 边界契约经人类批准后才动手**
3. **脚手架即 T0**：迭代目录（技术方案/工时预估/会话提示词骨架）+ 每线迭代目录（留言板 + 实施计划/实施记录）+ 管控台账（assets/管控台账模板）——全部作为实施计划首个任务包 T0 由总控执行、纳入实施记录，不游离于计划外
4. **契约先行**：总控牵头产出跨线契约文档（assets/契约文档模板：协议＋接口，交互形态分型，完备性判据=可 mock 三条件），**经人类批准冻结基线版**；各线基于契约隔离开发 + mock 自测，自测通过是联调开启条件（《多会话协作规范》§9）
5. 工时预估按四元口径（assets/预估模板）：日历周（核心交付与验收收尾分开估）+ 决策点数 + 外部等待窗口 + 复验轮次预算，另列存量缺陷暴露预算
6. 输出**批任务卡** + 管控会话启动卡（assets/启动卡模板·迭代档）——**所有路径写绝对路径，每线工作目录显式注明**
7. 用户按时机表**逐批**开会话、粘贴任务卡（v1 初始消息手动发；批毕即终，新批新会话）
8. **必做**：总控部署守望（盯全部留言板，**唯一部署方**）+ 定时兜底（assets/兜底心跳提示词模板）

## 3. 运行循环（轮纪律）

每轮固定动作链（完整版见《多会话协作规范》§3~§6）：

```
轮开始：读留言板「## 管控指令」→ 执行未标[已执行]的指令（优先级高于本批既有任务）
        接受指令先在「线反馈」登记"开始 #N，时间"——执行中状态必须板上有痕
轮结束：写「## 线反馈」（一次且仅一次）→ 清板上待办 → 一句话汇报
        （守望由总控常驻部署，批会话不部署、不重启守望）
批结束：按交付清单收口（提交＋回执含直连沟通摘要＋实施记录终态＋沉淀＋tmp 清理），
        总控"提交/板/记录"三对齐核验后销批（《多会话协作规范》§15）
```

铁律：

- **线级 T0 先行**：各线开工的第一个批=环境就绪（工具链＋项目跑通＋产出《环境与工具链.md》），完成前不启动功能开发（《多会话协作规范》§11）；
- 禁止无界长任务，长任务拆轮；**超批工作不扩批**——登记新任务交总控派新会话；
- **守望归总控**：守望/兜底全部由总控部署；基线双场景（写板方轮末重部署=清待办后删基线；兜底重启=不删基线）详见《多会话协作规范》§5；
- **长命令禁止傻等**：构建/编译/打包/安装/部署一律后台执行 + 结束标志轮询（assets/wait_for.py），禁止固定时长 sleep；
- 回执勿美化：描述与实测证据一致，界面类"通过"只认可见内容；核验提示词中性（不含预期值）。

## 4. 总控输出契约（总控会话每次回复生效）

- 每次回复末尾固定带「各线指令」区，无指令也要明写"无"，不得省略；
- 每线指令各自独立代码块、指令自包含（禁"沿用上一条/在上条追加"）；
- 同附「依赖/时机一览表」按发送顺序排列，每条注明"现在发/等X后发/暂不发（原因）"，含是否现在开线；
- 指令=需要线执行动作的消息，纯告知不进指令区（除非某线正等该信息解锁）；
- 结构化信息优先用表格。（全文见《多会话协作规范》§8）
- 回复**语言**按《沟通规范》执行：人话优先、内部编号首次出现配一句话解释、长汇报开头一句话摘要、叙事有过渡——结构归输出契约，语言归沟通规范。
- **指令发出即登记《指令台账》**（assets/指令台账模板）：一行一条（#N/日期/目标线/来源/摘要/状态），总控与用户直连的任务/决策统一留痕——《多会话协作规范》§16。

## 5. 异常路由

| 异常 | 处置 |
| --- | --- |
| 守望死亡/心跳停超 10 分钟 | 定时兜底自动重启（**不删基线**，启动自检报漏，见 assets/兜底心跳提示词模板）；无兜底时提示用户对会话发"自检"（先读板清待办，再删基线重部署） |
| 回执与实况不符 | 独立核验（像素级/磁盘实况对照）→ 纠偏指令 + 同类全量排查 |
| 编号撞号 | 沿用在后者顺延并注记（《决策与台账规范》） |
| 出现跨仓/多边界依赖 | 批量档升迭代档，重走拆线批准关卡 |
| 联调中发现缺陷 | 回流对应开发线修复；联调期间其它线冻结代码变更（《多会话协作规范》§10） |
| 两线对同一契约理解/实现不一致 | 以契约冻结版为准；差异与缺口走管控登记变更（编号+受影响线重评），禁止各自漂移（《多会话协作规范》§9） |
| 同阶段累计回炉 ≥2 次 | 请人类直接介入（逐条答复关键问题或拆小需求） |
| 会话上下文将尽（批内异常） | 用 assets/续接提示词模板开续接会话接完本批（正常应靠批粒度划分避免） |
| 人类直连会话沟通、总控不在场 | 三层保险：批临终清单必含直连沟通摘要＋人对会话说"记到板上"＋总控三对齐对账；任务级/决策级直连入指令台账（《多会话协作规范》§14/§16） |
| 批交付三对齐失败（有提交无回执/有回执无记录/有变更无登记） | 总控打回补齐登记，对齐后台账销批（《多会话协作规范》§15） |

## 6. 收尾序列

1. 一致性核对：代码/文档/台账/留言板双向一致，含报告头部日期=最新版本时点
2. 验收：迭代档出验收报告（按《验收报告规范》，版本目录制）；批量/单点档排查报告即可
3. 复盘：按 assets/复盘报告模板（含"沉淀最终态规则"检查项），放迭代目录 `复盘报告\复盘报告_{{时间戳}}\` 版本目录，时点快照不改旧版
4. 销毁监控与清点：停守望后台任务、**删除定时兜底任务**、销毁按需测试实例；**tmp 清点**（留档价值的挪至实施记录引用处，其余删除——《多会话协作规范》§13）
5. 台账归档：logs.csv 记终态（按《信息记录规范》）

## 8. 范围与边界（v1）

- 自驱动 v1：批初始消息**手动发**（任务卡）；守望不健康由定时兜底或人工"自检"恢复
- 自动化只覆盖机械动作（叫醒/送信），**决策与复验永远到人**
- v2 全自动化（app-server 驱动会话）属技术储备，见自驱动方案文档，不在本 skill v1 范围
- 规程层 harness 无关；守望/后台任务/定时任务语义以 ZCode 实证，其他工具降级为人工驱动
