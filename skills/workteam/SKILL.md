# Workteam——多会话协作规程作业手册

一套"人类只做决策与验收，AI 会话自组织执行"的协作规程。你被调用时充当规程执行者：引导用户定档与启动，按规程组织会话协作，维护台账与核验纪律。

**第一原则**：一切状态外置于文件（留言板/管控台账/实施记录）。会话是易耗品，随时可死可换；文件是唯一事实源，消息不会丢只会慢。

## 0. 开工前置

首次使用按序通读三份：

1. `references/规模适配规范.md`——定档
2. `references/多会话协作规范.md`——角色、留言板与轮纪律
3. `references/项目协作约定.md`——编号体系与状态块

其余规范按 §6 索引按需加载，不必预先全读。

## 1. 第一步：定档

判据一句话：**要不要开第二个会话**。

- 不开 → 单点档；开但人类直接盯 → 批量档；需要管控会话代人类盯 → 迭代档。
- 拿不准 → 就高不就低；档位构件表与升降档规则见《规模适配规范》。

## 2. 冷启动序列

### 2.0 通用四问（任何档位先问清）

1. 目标与交付物是什么（一句话 + 验收标准）
2. 涉及哪些仓库/环境/账号
3. 有哪些外部依赖（设备/凭证/第三方）——立项即办的外部依赖清单
4. 期望日历窗口

### 2.1 单点档

plan 模式出计划 → 人类批准 → 执行 → 产物：`.docs/` 排查报告（按《报告修订规范》）。不开留言板、不部署守望。

### 2.2 批量档

1. 建工作目录 `.sprints/{{批次名}}/`：`留言板.md`（复制 `assets/留言板模板.md`）+ `实施记录.md`（复制 `assets/实施记录模板.md`）+ `tmp/`
2. 待办任务逐条以指令写入留言板「## 管控指令」区
3. 复制 `assets/watch_board.py` 到 `tmp/`，会话内后台运行，参数=本批留言板路径
4. 输出启动卡（`assets/启动卡模板.md`·批量档），用户开会话贴入
5. 决策走简表：待确认区 → 人类批复 → 回写为指令

### 2.3 迭代档

1. 四问之后产出**拆线方案**：按"仓库 × 依赖边界"拆线，每线一段边界契约（对内职责/对外接口/依赖前提）。拆线是方法、线数是结果，每个迭代重新推导，不沿用历史线划分
2. **【关卡】拆线方案 + 边界契约经人类批准后才动手**
3. 脚手架：迭代目录（`技术方案.md`、`工时预估.md`、`会话提示词.md` 骨架）+ 每线迭代目录（留言板 + 实施计划/实施记录）+ `管控台账.md`（复制 `assets/管控台账模板.md`）
4. 工时预估按四元口径（复制 `assets/预估模板.md`）：日历周（核心交付窗口与验收收尾窗口分开估）+ 决策点数 + 外部等待窗口 + 复验轮次预算，另列存量缺陷暴露预算
5. 输出各线启动卡 + 管控会话启动卡（`assets/启动卡模板.md`·迭代档）
6. 用户手动开各会话、粘贴启动卡（v1 初始消息手动发）
7. 管控会话部署守望（盯全部留言板，参数=各板路径）+ 会话内 cron 兜底（30~60 分钟，读心跳文件判活，死则提示人类）

## 3. 运行循环（轮纪律）

每轮固定动作链（完整版见《多会话协作规范》§3）：

```
轮开始：读留言板「## 管控指令」→ 执行未标[已执行]的指令（优先级高于既有计划）→ 标记[已执行]
轮结束：写「## 线反馈」（一次且仅一次）→ 删守望基线重扫 → 重部署守望 → 一句话汇报
```

铁律：

- 禁止无界长任务，长任务拆轮；
- 基线重扫必须把本轮自身写入纳入基线（防自唤醒死循环的命门）；
- 回执勿美化：描述与实测证据一致，界面类"通过"只认可见内容；
- 核验提示词中性：不含预期值。

## 4. 异常路由

| 异常 | 处置 |
| --- | --- |
| 守望死亡/心跳停超 10 分钟 | v1：提示用户对对应会话发一句"自检"（读板恢复→清待办→重部署守望）；自动化方案见《ZCode多会话自驱动工作方案》§三（v2 储备） |
| 回执与实况不符 | 独立核验（像素级/磁盘实况对照）→ 纠偏指令 + 同类全量排查 |
| 编号撞号 | 沿用在后者顺延并注记（《决策与台账规范》） |
| 出现跨仓/多边界依赖 | 批量档升迭代档，重走拆线批准关卡 |
| 同阶段累计回炉 ≥2 次 | 请人类直接介入（逐条答复关键问题或拆小需求） |
| 会话上下文将尽 | 用 `assets/续接提示词模板.md` 重开会话，从实施记录无损恢复 |

## 5. 收尾序列

1. 一致性核对：代码/文档/台账/留言板双向一致，含报告头部日期=最新版本时点
2. 验收：迭代档出验收报告（按《验收报告规范》，版本目录制）；批量/单点档排查报告即可
3. 复盘：按 `assets/复盘报告模板.md`，放迭代目录 `复盘报告/复盘报告_{{时间戳}}/` 版本目录，时点快照不改旧版
4. 销毁监控：停守望后台任务、删 cron 兜底、销毁按需测试实例
5. 台账归档：logs.csv 记终态（按《信息记录规范》）

## 7. 范围与边界（v1）

- 自驱动 v1：初始消息**手动发**（启动卡）；守望不健康**人工恢复**（对会话说"自检"）
- 自动化只覆盖机械动作（叫醒/送信），**决策与复验永远到人**
- v2 全自动化（app-server 驱动会话）属技术储备，见自驱动方案文档，不在本 skill v1 范围
- 规程层 harness 无关；守望/后台任务/定时任务语义以 ZCode 实证，其他工具降级为人工驱动
