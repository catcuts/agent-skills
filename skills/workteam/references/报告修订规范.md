# 报告修订规范

## 一、适用范围

本规范适用于 `.docs/` 目录下所有排查报告、分析报告的创建和修订。

## 二、报告命名格式

```
<问题简述>_<YYYYMMDD-HHMMSS>.md
```

- **问题简述**：用简短中文描述问题核心，如"设备登录后信息不同步排查报告"
- **日期时间**：报告创建时的时间，格式 `YYYYMMDD-HHMMSS`，24小时制
- **分隔符**：问题简述与日期时间之间用下划线 `_` 连接
- **示例**：`设备登录后信息不同步排查报告_20260328-104127.md`

## 三、报告文件副本

每次修订报告时，如引用或参考了代码文件，需将相关文件复制一份到对应修订版本的副本目录中。

### 3.1 副本目录结构

```
.docs/codecopys/<报告文件名去除扩展名>_<修订版本号>/
  └── <按项目中的相对路径还原文件>
```

- **报告文件名去除扩展名**：与报告文件名一致（不含 `.md`），如 `设备登录后信息不同步排查报告_20260328-104127`
- **修订版本号**：与修订历史中的序号对应，从 1 开始递增

### 3.2 示例

报告 `设备登录后信息不同步排查报告_20260328-104127.md` 的第 1 次修订副本目录：

```
.docs/codecopys/设备登录后信息不同步排查报告_20260328-104127_1/
  └── devices/
      └── iptalk/
          ├── protocol.py
          ├── util.py
          └── website.py
```

### 3.3 注意事项

- 副本目录仅保留本次修订实际参考或引用的文件
- 副本文件应与当时项目中的文件内容一致，不做任何修改
- 如某次修订未引用或参考任何代码文件，则无需创建副本目录

## 四、修订历史格式

每份报告末尾必须包含修订历史表格，**按倒序排列**（最新修订在最上面），格式如下：

```markdown
## 修订历史

| 序号 | 修订时间 | 修订内容 | 基于的 Git 提交 SHA | 参考文件副本目录 | 问题状态 |
|------|----------|----------|---------------------|------------------|----------|
| 2 | YYYY-MM-DD HH:MM:SS | <修订内容简述> | `<完整的commit SHA>` | `.docs/codecopys/<目录名>_2/` | 处理中/已处理 |
| 1 | YYYY-MM-DD HH:MM:SS | <修订内容简述> | `<完整的commit SHA>` | `.docs/codecopys/<目录名>_1/` | 处理中/已处理 |
```

### 4.1 字段说明

| 字段 | 说明 |
|------|------|
| **序号** | 从 1 递增，每次新修订插入表格最上方 |
| **修订时间** | 本次修订完成的时间，格式 `YYYY-MM-DD HH:MM:SS` |
| **修订内容** | 简述本次修订做了什么 |
| **基于的 Git 提交 SHA** | 修订时项目 HEAD 所指向的 commit SHA（可简写前 7 位） |
| **参考文件副本目录** | 相对于项目根目录的副本目录路径 |
| **问题状态** | `处理中`（问题尚未解决）或 `已处理`（问题已解决） |

### 4.2 注意事项

- 每次修订在表格**顶部插入**新行（倒序排列），不修改历史行
- 问题状态仅当问题完全解决时才标记为 `已处理`
- 基于的 Git 提交 SHA 用于回溯当时代码状态，便于 `git checkout` 恢复上下文
- 报告头部日期随最新修订同步更新，与修订历史表首行的修订时间一致
