# 多会话协作规范

> 适用范围：同一迭代/批次内两个以上 AI 会话并行工作的场景。编号体系、状态块、修订留痕、验收清零以《项目协作约定》为准。

## 1. 会话角色

- 人类：决策者与验收者。批复决策、复验证据、外部协调、驱动节拍。
- 管控会话：任务编排、回执独立核验、跨线分流、状态外置记账；不参与业务开发。
- 线会话：按仓库/边界并行执行任务。细粒度打磨可由人类直连某线（直连模式），事后由该线在留言板登记。
- 一次性子代理：环境部署等独立任务；不可向人类提问，失败即返回问题报告（已执行步骤/失败点/原因/建议）。

## 2. 留言板（跨会话通信唯一通道）

- 每线一块，三区：
  - `## 管控指令`：管控会话写，带序号+时间戳；线会话执行后原地标记[已执行]。
  - `## 线反馈`：线会话一条消息结束时写一次且仅一次，过程中不写。
  - `## 待确认`：线会话写，编号+背景+可选项，由管控会话分流（QA 自答留痕 / QB 升级人类）。
- 跨会话不直接修改对方产物；一切经留言板或人类转交。

## 3. 轮纪律

- 轮开始：读本线留言板「## 管控指令」，执行未标记[已执行]的新指令（优先级高于既有计划）。
- 轮结束：写「## 线反馈」→ 清板上待办 → 删守望基线重扫 → 重部署守望 → 一句话汇报。
- 禁止无界长任务；长任务拆轮。
- 基线重扫必须把本轮自身写入纳入基线（防自唤醒死循环的命门）。

## 4. 写入时序

- 写板前重读锚点，写后复读标记归属。
- 共享文档修订前先读其状态块；新版本行按版本号倒序插入。
- 多会话禁止同时编辑同一文件：读到某线正在修订的登记即串行等待。
- 台账类 CSV 单写者（见《信息记录规范》写入纪律）。

## 5. 守望与回执纪律

- 守望：会话后台进程轮询本线留言板，变化即唤醒会话。
- 守望不健康：v1 由人类对会话说"自检"恢复；自动化方案见《ZCode多会话自驱动工作方案_调研验证与踩坑全记录_2026-10-16》。
- 回执勿美化：描述与实测证据一致；界面类"通过"只认可见内容。
- 核验提示词中性：不得含预期值。
- 拿不准是否属重构级 → 按重构级中止，输出回炉说明。
