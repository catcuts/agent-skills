# 项目协作约定

## 文件

- 需求说明.md、线框图.html —— 阶段一产出
- 技术方案.md —— 阶段二产出（前端、接口、后端、数据）
- 实施计划.md、实施记录.md —— 阶段三产出并随实施维护
- 回炉说明.md —— 各阶段中止时追加 RB-#（全项目连续编号，不随阶段重置）
- 原始需求材料仅作追溯；与已验收文档冲突时，以后者为准。

## 编号体系

R 原文条目 ｜ F 功能点 ｜ P 页面（区块为 P#-B#）｜ Q 待确认项（QA＝已查相关信息做出的判断，供复核；QB＝需人类决策事项）｜ API 接口 ｜ TBL 数据表 ｜ SEQ 业务时序图 ｜ T 实施任务 ｜ DC 人类决策号 ｜ CC 跨线缺口/变更号 ｜ RB 回炉说明

- 决策/缺口编号全迭代连续，撞号时沿用在后者顺延并注记。
- 跨文档引用写法：《文档名》·QB3、《文档名》·SEQ-1、等；界面引用写法：线框图.html#P1。

## 术语

| 术语 | 定义 |
| --- | --- |
| 项目（系统） | 可独立部署/交付的系统，由一个或多个仓库组成 |
| 仓库 | git 版本单元 |
| 目录 | 仓库内的模块/子项目（如 packages/web） |
| 端 | 项目内按运行形态划分的部分（前端/后端/小程序端）；端不必然成线——职能内聚优先，前后端常归同线 |
| 线 | 开发责任域（按"仓库 × 依赖边界 × 职能内聚"划分，可跨仓库跨目录）；状态载体为线迭代目录文件，工作由按批分配的临时会话执行——**线 ≠ 会话** |
| 协议 | 跨交互点的通信与流程约定：认证、时序、主题/指令命名规范、码表 |
| 接口 | 系统间/端间**可独立描述的交互点**，带交互形态字段（HTTP / 消息主题 / 长连接指令 / 回调 / …）；HTTP 型含路径/方法/出入参/错误码，消息型含主题/消息体结构/码表/示例报文 |
| 契约 | 协议与接口的合称；**契约先行**＝先定契约（可 mock 三条件齐备，见《多会话协作规范》§9）再开发 |

## 状态块（每份 md 头部）

> | 版本 | 日期 | 产出阶段 | 状态 | 修订会话 | 动了哪些编号 | 原因 |
> | -- | -- | ---- | -- | ---- | ------ | -- |
> | v# |    |      |    |      |        |    |

- 行按版本号倒序排。
- 「日期」＝最新修订日期，随内容修订同步更新。

## 修订留痕

下游会话修订上游文档：直接修改文件 ＋ 登记修订记录 ＋ 修订清单随本阶段输出一并交人类验收。
- 多会话并发时的写入时序见《多会话协作规范》。

## 验收即清零

人类验收时：QA 抽核（不通过转 QB 处理）；QB 逐条答复 / 授权“按推荐” /明确挂起并记录影响。答复由原阶段会话落入正文并登记修订记录后，文档方可定稿（状态改为已验收）。

## 其他

- 文档由 git 管理，验收通过即 commit；回炉重造可 diff。
- 同一阶段累计回炉 ≥ 2 次：建议人类直接介入（逐条答复关键问题，或把需求拆小）。
- 临时文件（例如临时脚本等）有组织地放在 `.sprints/{{本次迭代标题}}/tmp` 目录或子目录下；命名/生命周期/禁地细则见《多会话协作规范》§13 临时文件纪律。
