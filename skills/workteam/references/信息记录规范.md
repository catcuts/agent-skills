# 记录执行细则

存储文件：项目根目录下 data/ 目录中的 logs.csv、assets.csv、flows.csv（当前使用 CSV 格式，未来可更换）。

## logs.csv — 操作日志

- 以事件/事务为单位记录（非单个操作）
  - 事件 = 有明确开始和结束的完整业务单元
  - `detail` 字段需包含该事件的所有步骤详情
- `datetime` 是事件开始时间，`created_at` 是记录写入时间
- `target_type=asset` 时，`target` 填 assets.csv 中的 `id`，形成关联
- `result` 取值：success / failed / partial
- `tags` 按内容自由打标，便于筛选；协作编号（DC/CC/RB/T/QA/QB）一并入 tags，日志可按编号检索
- `id` 自增，写入前需读取现有最大 id

## assets.csv — 资产登记

- 新增资产时录入，状态变更时更新（同时更新 `updated_at`）
- `entry` 为资产入口地址，随 category 变化：服务器填 IP、域名填 URL、文件填路径
- `auth_type` 决定 `auth_info` 的 JSON 结构：
  - `password` → `{"username":"...", "password":"..."}`
  - `key` → `{"username":"...", "key_path":"..."}`
  - `token` → `{"token":"..."}`
  - `none` → `{}`
- `id` 自增，写入前需读取现有最大 id

## flows.csv — 流程文档

- 每条记录是一个完整可复用的流程，不是单个步骤
- `steps_doc` 用 Markdown 自由格式描述，可包含标题、说明、命令块、注意事项
- 完成一套新流程后整理录入，供下次同类场景直接参照执行
- `id` 自增，写入前需读取现有最大 id

## 三表关联

```
logs.target (当 target_type=asset) → assets.id
logs.detail / logs.tags → flows.name / flows.tags (通过标签或名称间接关联)
```

## 写入纪律

- 三表单写者：仅管控会话（或人类）写入；其他会话经留言板申请代写
- 写前读取现有最大 id 后立即写入；写入失败（文件已被并发修改）则重读重试

## 敏感信息

- data/ 目录必须 gitignore，不入 git
- `auth_info` 推荐只存路由（指向明文值所在的 gitignored 第一手记录位置，如实例记录文件）；值不在本表维护，防止复制腐烂
