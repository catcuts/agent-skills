# README 措辞通用标准

> 适用范围：本技能对人类的一切说明文档（README.md、README.html 及后续新增的给人阅读的说明页）。

1. **称呼与实物当前形态一致**——标题与通篇定位必须反映项目当下的形态与规模，不沿用早期阶段或旧用途的叫法；东西变了，名字和口吻要跟着变。
2. **开篇交代应用场景**——文档最前面就应说明"它给什么用、适合哪些场景"，让读者先建立使用图景，再进入细节；不能只给抽象定义。
3. **不使用环境专属的称呼**——只在特定部署、特定语境里才有意义的修饰词和代号（如按位置、按批次临时起的称呼）不得出现在文档里；一律使用角色名或功能名。
4. **术语首现必须先解释**——缩写、代号、专有名词在第一次出现处就地定义，或以术语表前置；默认读者是第一次接触。
5. **指令写明执行者与作用对象**——凡"做某事"的表述必须补全：谁来做、做到哪个对象上；缺主语或缺宾语的指令无法被执行，也容易产生歧义。
6. **前提条件要完整**——前提清单需覆盖全部需事先准备的角色与材料，不能默认读者已知某些事项需要提前备好；每项注明归属与要求。
7. **章节之间要有过渡**——章节不能是信息块的拼接；章与章之间应有承接性表述，把逻辑关系、递进关系显性写出来，让读者不必自己费力拼出全貌。
8. **不允许孤立的信息块**——任何章节要么融入主线（承接前后文），要么给出明确的收尾信号（如附录式定位），不能悬空放置、与上下文毫无关联。
9. **同一信息只在一处展开**——重复出现的两处内容应合并为一处；多处展开既冗余，也增加维护与失同步的风险。
10. **图必须配解释**——架构图、示意图不能裸放，必须附文字说明，讲清图中各元素及相互关系，否则读者只能自行猜测图的意图。
